## 7.2 성능 (1,000건, 가정: 동시 사용자 ≤ 20명)

초기 로드는 캐시를 끄고 Fast 4G(9Mbps/165ms)와 Slow 4G(1.6Mbps/150ms)를 에뮬레이션해 측정했습니다.

| 항목 | 목표 | 측정 | 판정 |
| --- | --- | --- | --- |
| LCP | 2.5초 이하 | 0.49~0.60초 | 통과 |
| 첫 데이터 표시 | 3초 이내 | 2.1~2.5초 (요청 43개, HTTP/1.1) | 통과(여유 적음) |
| 첫 화면 JS·CSS 전송(gzip) | 300KB 이하 | **54.4KB** (supabase 어댑터 사용 시 vendor +28.4KB = 82.9KB) | 통과 |
| 필터·검색 반영(4개 뷰, 15회 중 최대) | 100ms 이내 | 실행 5회에서 캘린더·대시보드는 모두 통과, **리스트 최대 71~108ms, 칸반 최대 43~155ms** | **불안정**(4회 중 1회 초과) |
| INP 근사(12~13회 상호작용) | 200ms 이하 | 실행별 최대 112~264ms, 3회 중앙값 **128~256ms** | **불안정**(목표 근처) |
| 실시간 반영 | 3초 이내 | 122~365ms | 통과 |
| 저장 응답 p95 | 500ms 이하 | local 어댑터 0.5~1.6ms(네트워크 없음) | **Supabase 서버 기준은 미검증** |

해석과 한계:

- 필터 갱신과 INP는 이 PC의 부하에 따라 같은 코드에서도 크게 달라졌습니다(병렬 실행 시 3배까지 증가). 그래서 성능 측정은 일반 e2e와 분리했습니다(`npm run test:perf`, 다른 작업 없이 실행).
- INP의 최악값은 대부분 **첫 대화상자 열기·첫 칸반 렌더 같은 콜드 스타트 상호작용**입니다. 같은 동작을 두 번째부터는 50ms 안팎이었습니다.
- 개선한 것: 칸반을 열마다 100장으로 제한(1,000건에서 필터 갱신 147ms → 약 70ms), 칸반 카드에 `content-visibility`(칸반 전환 160~176ms → 96~112ms), `modulepreload`(첫 데이터 표시 약 0.4초 단축). 서버를 HTTP/2로 두면 모듈 연쇄 로딩이 더 줄어듭니다.
- 검색 입력 지연 측정에 한글을 쓰면 앱의 long task 없이 300ms 대기가 보였고(`input→처리 0`), 이를 Playwright의 한글 합성 입력 쪽 현상으로 판단해 INP 측정 입력만 숫자로 바꿨습니다. **이 판단은 확정하지 못했습니다.** 실제 한글 입력에서 지연이 있는지는 실기기에서 확인해야 합니다.
- 저사양 모바일 CPU(스로틀링)에서의 측정은 하지 않았습니다 → **미검증**.

## 7.6 지원 브라우저

- 미지원 브라우저 안내(`js/compat.js`): `dialog` 없는 환경을 흉내 내 안내만 보이고 앱이 시작하지 않는 것을 확인했습니다.
- ES2021 이상 문법·`structuredClone`·지원 범위 밖 CSS를 쓰지 않는지 자동 점검합니다(`structuredClone`은 점검 중 발견해 제거).
- 사용 기능과 최소 버전은 [BROWSERS.md](BROWSERS.md)에 있습니다(MDN 호환성 데이터 기준).

## 기능 시나리오 (단계별 e2e)

작성자 식별·등록·수정·삭제·되돌리기·댓글, XSS(제목·설명·댓글·이름), 입력 검증, 세 뷰 항목 일치, URL 복원, 드래그·키보드 상태 변경과 실패 시 되돌림, 긴급 배지 경계, 캘린더(+N개·날짜 클릭·마감일 없음·월 이동), 대시보드 카드↔리스트 건수 일치, 두 사용자의 동시 편집 3종((a) 다른 필드 병합, (b) 같은 필드 확인창, (c) 삭제 우선), 연결 끊김 배너와 폴링 복구.

## PRD 확인 필요 (고치지 않고 보고)

1. **부서원 비활성**: PRD 7.4는 `members`에 조회·등록만 허용하는데 부서원 관리에는 「비활성」이 있습니다. 현재는 운영자가 SQL로 처리합니다.
2. **충돌 확인창 조건**: PRD 6.3의 5번(저장 시 `updated_at`이 다르면 확인)과 1번·S3(다른 필드면 둘 다 반영)이 겹칩니다. **내가 바꾼 필드를 다른 사람이 건드렸을 때만** 확인창을 띄우는 것으로 해석했습니다.
3. **브레이크포인트 토큰**: `--bp-sm/md/lg/xl` 이름은 4개인데 값은 3개(640/1024/1440)라 `xl`은 만들지 않았습니다.
4. **긴급 필터 추가**: 대시보드 카드를 누르면 같은 건수의 리스트로 가도록 필터에 「마감(임박/지연)」을 추가했습니다(PRD의 4개 필터 외).
5. **`deleted_at` 시각**: 소프트 삭제 시각은 클라이언트 시계입니다(생성·수정·완료는 서버).
6. **CSP `connect-src`**: 정적 메타 태그라 설정값을 읽을 수 없어 `*.supabase.co`로 두었고 배포 시 프로젝트 주소로 좁히도록 안내했습니다.
7. **최근 7일 완료**: 오늘 포함 7일(오늘−6일~오늘, 한국 시간)로 정의했습니다.
8. **성능 목표 달성 방식**: 필터 100ms·INP 200ms가 이 환경에서 불안정합니다. 목표를 유지할지, 칸반·리스트 렌더 상한을 더 낮출지 결정이 필요합니다.
